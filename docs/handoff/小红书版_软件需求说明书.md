# 小红书工具版 · 软件需求说明书（SRS）

> 文档版本：对应数据账本 `v0.27.2` · 整理日期 2026-11-02
> 交付物：`model-radar-xhs.zip`（小红书 APP 内运行的离线小工具）
> 本文档面向：重新实现或重新设计本产品 UI 的开发团队 / AI Agent。**范围仅限小红书工具版**——它与 GitHub 网页版（`model-radar.html`）是两个完全独立分发的产品，只共享同一份数据账本与计分口径（见《数据与算法交接_前10模型.md》），**UI 逻辑、页面设计、功能效果一律不与网页版通用**。

---

## 1. 引言

### 1.1 编写目的

定义「模型雷达图 · 小红书工具版」的功能需求、平台约束、非功能需求与验收标准，作为 UI 重设计、二次开发与测试验收的依据。

### 1.2 产品定位

在小红书 APP 容器内，为「按场景选 AI 模型」提供**手机竖屏、离线可用**的查询与对比工具；同时是作者「赛博摆渡人」的内容配套工具——通过平台关注机制完成进阶功能解锁，形成「工具有用 → 关注作者 → 评论区回流」的私域闭环。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 容器 | 小红书 APP 内嵌的小工具运行环境（WebView 沙箱） |
| 账本 / data.js | `window.RADAR_LEDGER` 全量数据：meta / dimensions / scenarios / models / evidence，与网页版同一份 |
| 口径 | 三档数据开关：全部来源 / 仅第三方榜单 / 含推理补全 |
| 场景 | 5 套任务场景权重：自媒体内容运营（默认）/ Agent与工作流 / 代码开发 / RAG知识问答 / 日常综合 |
| 门控（gate） | 关注作者解锁进阶功能的机制 |
| 位次分 | 全站唯一分值口径：族内 (升序名次−0.5)/n×100，语义见数据交接文档 §2.3 |

## 2. 总体描述

### 2.1 产品关系

```
共享（唯一）            独立（本产品自有的）
─────────────          ─────────────────────
radar/ 计分管线         手机竖屏原生 UI（底部三 Tab）
data/ 数据账本   ──→    关注门控、分享图集、置信带、状态记忆
        │
        └── data.js（同一份账本，构建时注入）
```

### 2.2 用户与使用场景

- **主要用户**：小红书站内关注 AI 工具内容的用户，用手机查询「我要做 X，该用哪个模型」。
- **典型动线**：笔记/评论区进入工具 → 默认榜单（Top 10）看结论 → 切场景看自己任务下的排名 → 选 2–3 个模型对比 → 生成分享图集发笔记/发评论 → 评论区重新打开工具恢复对比。
- **作者本人**：分享工具与卡片内容（署名引流）。

### 2.3 运行环境与硬约束

以下为容器能力快照（2026-10 实测基线）。**平台容器能力与规则随时在变，实施前必须以小红书小工具在线文档为准核对一遍**（查询顺序：官方在线文档 → 冻结基线比对 → 差异播报）：

| 约束 | 要求 |
|---|---|
| 网络 | **禁止任何联网请求**（无 fetch/XHR/外链资源），完全离线运行 |
| CSP | 禁止内联 `<script>` 与行内事件处理（`onclick` 等）；脚本必须外置经典 JS（非 module） |
| JS 引擎 | ES2017 上限（Chrome 61 基线）；不用可选链/空值合并等新语法 |
| CSS | 老内核兼容：`flex gap` 需探针降级、`grid-gap` 别名、`env()` 安全区需降级路径 |
| 安全区 | 容器 `viewport-fit=cover` 全屏渲染；Android WebView `env(safe-area-inset-top)` 返回 0，必须用「固定基线在前、env 增强在后」的双层结构（顶部 ≥28px、底部 tabbar 同理） |
| 跳转 | 禁止 `target=_blank` 站外跳转；不得包含任何 GitHub 元素或站外链接 |
| 体积 | zip ≤10MB，建议 ≤2MB（当前产物约 96KB） |
| 平台 API | 全部经 `window.xhs` 挂载；**API 不存在或调用失败一律降级放行，不得阻塞核心功能**（详见 §3.5） |

## 3. 功能需求

优先级：P0 = 无此不发布；P1 = 重要，尽量实现；P2 = 增强。

### 3.1 FR-1 信息架构（P0）

底部三 Tab 导航：**榜单 / 对比 / 关于**。竖屏优先，单手可达；Tab 切换不丢失已选状态。

### 3.2 FR-2 榜单 Tab（P0）

| 项 | 需求 |
|---|---|
| 场景切换 | 5 套场景可切换，默认「自媒体内容运营」；每行显示模型名、公司/开源徽章、八维刻度、场景综合分、全池名次 |
| 数据口径 | 三档分段开关（全部来源 / 仅第三方榜单 / 含推理补全），语义见数据交接文档 §2.7；前端只换数据、不重算分数 |
| 默认范围 | **默认只显示前 10 名**；「查看全部（33 个）」为门控进阶功能（FR-5） |
| 搜索 | 按模型名定向查找；搜索结果不受「前 10 上限」约束（搜索是定向查找，不是浏览全部） |
| 置信带 | 综合分显示 ±σ 置信带（公式见数据交接文档 §2.8）；两模型分差在 ≈平阈值内时不下胜负结论 |
| 低覆盖提示 | 覆盖维度少的模型应可辨识（缺维让权语义：缺数据 ≠ 0） |
| 详情 | 点行进模型详情：八维分数与全池名次、逐维证据（来源/日期/原始分/位次分/基准族）、单基准 † 标记、推理值标识 |

**验收**：33 模型 × 5 场景 × 3 口径下数值与账本一致；待定格不显示为 0。

### 3.3 FR-3 对比 Tab（P0）

- 选择 2–3 个模型对比（可从榜单行直接加入）。
- 雷达叠加图：**遵守「缺数据 ≠ 0」红线**——缺维折线断开（不连圆心）、轴端空心标记；只有第一个选中模型填充，其余只走线。
- 逐维对照：分数、全池名次、≈平判定、单基准 †。
- 场景取舍视图：5 场景下各候选的综合分与名次、分工建议。

### 3.4 FR-4 关于 Tab（P0）

产品说明、计分口径摘要（位次分语义、缺≠0、三口径）、数据来源与数据日期、作者署名、免责声明（「数据来自公开榜单，仅供选型参考」）。

### 3.5 FR-5 关注门控（P0）

用平台 API `getFollowStatus` / `followAuthor`（客户端 9.51+）实现「关注作者解锁进阶功能」。

**锁定范围（仅三处，核心功能永远免费）**：
1. 「含推理补全」口径；
2. 「查看全部模型」（默认只给前 10 名）；
3. 「生成分享卡」入口。

**行为矩阵（必须完整实现，历史 bug 均出自此处）**：

| 场景 | 行为 |
|---|---|
| API 不存在（浏览器预览 / 旧容器） | 不锁任何功能（降级放行） |
| `getFollowStatus` 查询失败（-1）或异常 | 不锁（降级放行），状态记 `query-fail` |
| 客户端版本低于 9.51 | 不锁；版本判定须**同步值→异步 `getLaunchOptions()` 两级读取**（同步值在部分真机上缺失，只读同步会误判旧客户端而整体放行） |
| `follow_status = 1`（已关注） | 解锁全部 |
| `follow_status = 2`（作者本人） | 自动解锁（设计行为） |
| `follow_status = 0`（未关注） | 显示引导：点「关注解锁」→ 调 `followAuthor` |
| `followAuthor` resolve 返回 -1（文档明确：失败也 resolve，不走 reject） | **必须用 `getFollowStatus` 复查**，按复查结果给三种反馈之一（解锁 / 临时解锁 / 保持锁定提示），不得静默无反应 |
| 用户拒绝授权（错误码 20002） | 对应 toast 提示 |
| 当日关注操作达上限（错误码 15404） | 对应 toast 提示 |
| 深链进入 `scope=inf` 且未解锁 | 回退「全部来源」并弹出关注引导条 |
| 防抖 | 门控请求进行中禁止重复触发（`busy` 状态） |

**验收**：真机上未关注的非作者账号能看到锁与引导（**作者本人账号永远自动解锁，不能用作者账号验证门控效果**）；mock `window.xhs` 可全流程回归四形态：同步值 / 仅异步值 / 旧版本放行 / 无来源放行。

### 3.6 FR-6 分享图集（P0）

对比页生成 **1200×1600（3:4）多图套装**，Canvas 离线绘制：

- **主卡 = 模型对比卡**：多模型并置墨带、结论行、五场景名次对比条、雷达叠加、多列名次清单（优者/劣者字重区分）；
- **副卡 = 每个选中模型的能力档案卡**：大字模型名、综合分、五场景名次、雷达+名次清单（含 ±σ）、强项/待加强、页脚二维码与作者署名；
- 单选一个模型时自动补入「当前场景第 1 名」作为对比对象；未选任何模型时默认对比 Top 3；
- 弹层预览：主预览 + 缩略条，逐卡勾选（至少保留一张）；
- 分享卡维度标签用**书面短名**（推理/代码/指令遵循/Agent/长文本/可靠性/内容创作/图片制图）；应用内白话别名（动脑子/少瞎编等）**不得上对外物料**。

### 3.7 FR-7 分享三通道（P0）

| 通道 | API 与要求 |
|---|---|
| 发笔记 | `writeTempFile` 落盘多图 → `postNote`（title ≤20 字、content ≤1000 字、`image_resources` 多图，平台文档支持最多 18 图）。**成功回调只代表发布页被唤起，toast 文案不得写「已发布」** |
| 发评论晒卡 | `interactionOpenApi`（9.49+）：`writeTempFile` 本地路径作 `media_bean` 图片 + `miniToolSnapshotInfo` 携带 scene/scope/models 快照（≤2KB）→ **评论区重新打开工具可恢复该次对比（引流闭环）**；版本不足时降级 toast |
| 存相册 | `saveImageToPhotosAlbum`，多张时循环保存 |

### 3.8 FR-8 状态记忆与深链（P1）

- 本地记忆 key `radar-state-v1`：scene / scope / selected / hidePending；存储用平台 `setStorage/getStorage`（9.46+），无则回退 localStorage；读写失败静默。
- **深链优先、记忆只补缺**：URL hash 参数（scene/scope/model/view 等）存在时以深链为准。
- **`scope=inf` 永不从记忆恢复**（防止绕过关注门控）。

### 3.9 FR-9 页脚二维码（P2）

右下角自绘二维码（Canvas 逐模块绘制，矩阵数据构建时由 Python `qrcode` 预生成后以字符串内嵌，不引第三方 JS）。载荷 = 作者小红书主页短链（当前过渡态：小红书号文本）。

### 3.10 FR-10 AI 选型文案（P2，待平台开通）

平台 AI 文本生成能力（§3.10 接口，`deepseek-v4-flash`，免费额度 100 次/天）生成发笔记正文文案。**前置条件：需平台运营为工具加白名单**，未开通前该功能不出现。

## 4. 外部接口需求

| 接口 | 版本门槛 | 用途 |
|---|---|---|
| `getFollowStatus` / `followAuthor` | 9.51+ | 关注门控 |
| `setStorage` / `getStorage` | 9.46+ | 状态记忆（localStorage 兜底） |
| `getLaunchOptions` | — | 构建版本读取（同步值缺失时异步回退） |
| `writeTempFile` | — | 分享图落盘 |
| `postNote` | — | 发笔记（多图） |
| `saveImageToPhotosAlbum` | — | 存相册 |
| `interactionOpenApi`（评论晒卡） | 9.49+ | 发评论带图 + 快照回流 |
| 震动反馈 | — | 轻交互反馈（存在性检查 + try/catch） |

数据接口：唯一的输入是 `data.js`（`window.RADAR_LEDGER`），字段契约见《数据与算法交接_前10模型.md》§8 与 JSON 结构说明。页面**只按口径选用 `scores / scoresTp / scoresInf`，不做任何分数重算**。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 33 模型全量渲染首屏无卡顿；Canvas 分享卡生成 ≤1s 量级 |
| 体积 | zip ≤2MB（当前 ~96KB）；字体子集化（Geist woff2 ×4 随包） |
| 兼容 | Chrome 61 / ES2017 基线；老内核 CSS 探针降级；iOS/Android 真机安全区双层规则 |
| 健壮性 | 所有平台 API 调用必须「存在性检查 + try/catch + 失败降级」；任何单点 API 异常不得导致应用启动失败（历史教训：启动链上一个未定义函数使整页死掉） |
| 文案 | 对外物料（分享卡、发笔记文案）用**信达雅书面语**；白话别名仅限应用内引导；产品署名「赛博摆渡人」 |
| 合规 | 数据来自公开榜单，标注「仅供选型参考」；不含价格/套餐（能力对比工具定位）；禁站外跳转 |
| 视觉 | 分享卡构图必须原创，不得复刻第三方参考卡 |

## 6. 数据需求

1. 数据唯一来源：主版构建产物中内嵌的账本 → `data.js`。更新流程：主版数据变更后重跑 `python scripts/build_xhs.py` 取同一份账本重新出包。
2. 数据内容、口径与语义红线（缺≠0、池内相对分、单基准 †、三口径、置信带公式）全部见《数据与算法交接_前10模型.md》。
3. 全量 33 模型 / 722 证据随包内置；默认展示前 10 是产品策略（门控），不是数据限制。

## 7. 验收与测试要求

1. **静态审计**：官方审计脚本 `audit_artifact.py model-radar-xhs.zip` 必须 PASS（内联脚本 / ES 语法 / 外链 / 体积等规则）。
2. **本地预览**：`python scripts/preview_xhs.py`（127.0.0.1:8642，必须带 `Cache-Control: no-store`，防旧脚本误判「改了没生效」）。浏览器预览无 `window.xhs` 时门控默认放行；`?lock=1` 强制锁定态预览（会话记忆，`?lock=0` 解除）。
3. **mock 验证**：注入 `window.xhs = { launchOptions:{...}, miniTool:{ 间谍函数 } }` 走真实生产路径，覆盖门控四形态与分享三通道。
4. **真机三步验证**（AI 不可代做，须人工完成）：创服平台模拟器 → Android 真机扫码 → iOS 真机扫码。重点：分享卡 Canvas 渲染、发笔记拉起、相册权限、关注解锁真实回传、状态记忆持久化、安全区不塌进状态栏。
5. **回归红线**：任一版本发布前，门控行为矩阵（§3.5）全分支回归。

## 8. 明确不做（已否决，勿重新提议）

- 联网、站外跳转、外链资源（容器规则 + 离线承诺）；
- 价格 / 套餐展示（能力对比工具定位，雷达轴不含价格是全项目红线）；
- 站内排行榜、云存储、随机抽模型（与工具气质不符 / 价值低 / 用户带目的而来）；
- 跨版对齐：不把网页版的组件、文案、交互搬进小红书版，反之亦然；
- 把应用内白话别名用于对外分享物料。
