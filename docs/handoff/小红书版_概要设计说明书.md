# 小红书工具版 · 概要设计说明书（HLD）

> 文档版本：对应数据账本 `v0.27.2` · 整理日期 2026-11-02
> 配套文档：《小红书版_软件需求说明书.md》（需求与验收）、《数据与算法交接_前10模型.md》（数据与计分口径）
> 本文档描述现有实现的总体架构、模块划分、关键流程与设计决策，作为 UI/交互重设计与二次开发的基线。**范围仅限小红书工具版；与 GitHub 网页版不通用。**

---

## 1. 系统概述

单页离线小工具，运行于小红书 APP 容器（WebView 沙箱）。无后端、无网络请求；全部数据随包内置。运行期技术基线：**ES2017 / Chrome 61、经典外置脚本、CSP 禁内联、老内核 CSS 降级**。

设计目标（按优先级）：
1. **数据语义零失真**——页面只按口径选用账本数据，不重算任何分数；
2. **平台 API 全降级**——任何 API 缺失/失败都不阻塞核心功能；
3. **竖屏单手操作**——底部三 Tab、行内渐进展开；
4. **私域闭环**——关注解锁、分享回流、作者署名。

## 2. 总体架构

### 2.1 构建期视图

```
model-radar.html（主版交付物，内嵌账本数据区）
        │  python scripts/build_xhs.py（正则提取数据区 → json 校验）
        ▼
window.RADAR_LEDGER = {...}   ← 与主版逐字节同一份账本
        │
xhs_template/                 模板与静态资源
  ├─ index.html   （壳 + {{APP_CSS}} 占位符）
  ├─ app.css      （样式，构建时内联进 index.html）
  ├─ app.js       （应用逻辑，原样拷贝）
  ├─ fonts/       （Geist / Geist Mono woff2 子集 ×4）
  └─ author.png   （作者头像，署名与分享卡用）
        │
        ▼
dist-xhs/                     中间产物：index.html / data.js / app.js / 静态资源
        │  zip 打包（ZIP_DEFLATED）
        ▼
model-radar-xhs.zip           最终交付物（项目根目录，当前 ~96KB）
```

数据更新链路：`data/*.csv → python build.py（主版）→ python scripts/build_xhs.py（本版）→ zip`。**两版共用同一份账本；任何分数问题都要回到 `data/` 表修，不许在任一版本的壳里改数。**

### 2.2 运行期视图（zip 内文件职责）

| 文件 | 职责 |
|---|---|
| `index.html` | 壳：DOM 骨架 + 全部 CSS（构建时内联）+ 三个 script 标签（data.js / app.js / 字体预载） |
| `data.js` | `window.RADAR_LEDGER` 全量账本（33 模型 / 722 证据） |
| `app.js` | 全部应用逻辑（单 IIFE，~1600 行） |
| 静态资源 | 字体、作者头像 |

### 2.3 信息架构（现状）

底部三 Tab：**榜单 / 对比 / 关于**。
- **榜单**（首屏即答案）：场景提问行 + 结论行 + 名次账本行（名次章 / 模型名与身份徽章 / 八维刻度 / 场景综合分 ±σ / 详情展开）；场景用下划线标签，口径为分段轨，工具行弱化；默认前 10，搜索不受限。
- **对比**：2–3 模型雷达叠加 + 逐维对照 + 场景取舍 + 生成分享图集。
- **关于**：口径说明、数据来源、署名、免责声明。

## 3. 数据契约与数据流

### 3.1 账本关键字段（本版实际消费）

```
meta                    version / built / disclaimer / noteMissing / scopeNote / infNote …
dimensions[8]           name / desc / alias（白话）/ plain / tasks / advice / note / stats
scenarios[5]            name + weights{维度: 权重}（已归一，合计 100.0）
models[33]              name / company / open / date / note / scores{维度:分}
                        / scoresTp（仅第三方口径，与全量不同才存在）
                        / scoresInf（含推理补全口径，同上）/ sf（单基准标记）
evidence[722]           m/d/src/cat/raw/scale/date/val/fam/famN/w/vend/inf
```

### 3.2 运行期数据流

1. **索引建立**：启动时把 `models` 按名建 `MODEL_IX`、`evidence` 按 `模型||维度` 建 `EVIDX` 倒排。
2. **口径选择**：`scopeScores(m)` 按 `state.scope` 返回 `scoresTp / scoresInf / scores`——**只换引用，不重算**。缺失维度返回 `undefined`（不是 0）。
3. **聚合计算**（展示时即时算，量级小）：
   - 场景综合分 `composite`：`Σ(W_d·v_d)/ΣW_d`，只对有分维度求和（缺维让权）；
   - 全池名次 `sceneRank/dimRank`：`1 + 严格更高者个数`（同分并列高位次）；
   - 覆盖度 `coverage`：有分维度计数。
4. **缓存失效**：池统计（每维 min/max）按口径缓存，切口径必须清缓存。

### 3.3 统计与置信带层

- `famWeight(n) = n<2 ? 0 : min(1,(n-1)/3)`（与管线公式同源，展示层只复述不另行发明）；
- `sigmaDim`：`σ_d = clamp(35/√(1+m_d), 5, 32)`，`m_d = Σ(w(n)·(n−1))`，缺维/仅推理按先验 30；
- `sigmaScene`：按场景权重合成；`sigmaRef`：满覆盖模型 σ 的中位数；`tieThreshold(a,b) = 2·√(σa·σb)/σref`。

## 4. 运行时模块划分（app.js）

单文件 IIFE，逻辑上分七层（依赖自上而下，禁止反向）：

| 层 | 成员 | 职责 |
|---|---|---|
| ① 兜底 | `window.onerror` | 全局错误捕获（真机无 devtools，错误上屏便于回报） |
| ② 数据与口径 | `scopeScores / sv / has / evsOf / isInf / singlesOf / sceneByName / composite / coverage / dimRank / sceneRank / pool / visible` | §3.2 的全部口径与名次逻辑；**唯一允许读账本的地方** |
| ③ 统计与置信带 | `famWeight / sigmaDim / sigmaScene / sigmaRef / tieThreshold / median` | §3.3 |
| ④ 平台服务 | `gate`（门控）/ `storeSave / storeLoad`（记忆）/ `toast / haptic`（反馈）/ JSAPI 调用封装 | 所有 `window.xhs` 访问集中在这层，带存在性检查 + try/catch + 降级 |
| ⑤ 状态与路由 | `state` / `readHash / syncHash` / `storeSave / storeLoad` | 单一 state 对象；深链优先、记忆补缺、`scope=inf` 不从记忆恢复 |
| ⑥ 渲染 | `renderChips / renderScope / renderHero / renderGate / renderAll…` | 全量重绘式渲染（无虚拟 DOM）；切口径清池缓存后 `renderAll` |
| ⑦ 分享引擎 | Canvas 绘制器（对比卡 / 档案卡）/ `writeTempFile` 输出 / 三通道发布 | 离线 Canvas 1200×1600；含页脚自绘二维码矩阵（构建期由 Python `qrcode` 预生成内嵌） |

## 5. 关键流程设计

### 5.1 启动链

```
load → window.onerror 挂载 → 账本索引建立（②）
     → readHash()（深链优先）→ storeLoad()（记忆只补缺；scope=inf 永不恢复）
     → gateRefresh()（门控判定，异步）→ renderAll()
```

⚠️ 启动链上**任何一步抛错 = 全页死掉**（空列表、点不动）。历史事故：重写时删掉一个版本判断函数，但存储层仍调用它 → 真机启动即 `ReferenceError`。**教训：删函数必须按函数名 grep 全部调用点；启动链每个函数都要有存在性检查或 try/catch。**

### 5.2 门控状态机（gate）

状态字段：`apiState ∈ {no-api, old-client(n), ok:fN, query-fail, preview-lock}`、`unlocked`、`busy`、`buildVersion`。

```
gateRefresh():
  读容器 buildVersion：同步值缺失 → 异步 getLaunchOptions() 回退（两级读取）
  无 API / 版本 <9.51 → unlocked=true（降级放行），apiState 记因
  有 API → getFollowStatus()
    ├ resolve 1/2 → 解锁（2=作者本人）
    ├ resolve 0 / -1 / 异常 → unlocked=true（query-fail 降级放行）
    └ 深链 scope=inf 且未解锁 → 回退 scope=all + 弹关注引导条
gateFollow():
  busy 防重 → followAuthor()
    ├ resolve 1/2 → 解锁 + 展开全部 + toast
    └ resolve -1/0（文档明确：失败也 resolve）→ getFollowStatus() 复查
        → 1/2 解锁 / -1 临时按降级口径解锁 / 0 保持锁定并提示
  错误码：20002 拒绝授权 toast；15404 当日上限 toast
```

**锁定物仅三处**：`scope=inf`、查看全部模型、生成分享卡。核心浏览/对比/搜索永远免费。

### 5.3 雷达与断口绘制（红线实现）

- 折线只连**有值顶点的连续段**：缺维断开、八维齐全才闭合填充、孤立单维画小点；缺维轴端画虚线空心圈。
- 多模型叠加：只有第一个选中模型填充，其余只走线。
- 任一选中模型缺维时，图形区顶部显示琥珀色提示条（「缺数据 ≠ 0 分……条形图缺维是待定空位」）+ 一键切条形图。

### 5.4 分享图集引擎

```
入口（对比页）→ 弹层：主预览 + 缩略条（点缩略图预览 / 点 ✓ 徽章勾选，至少一张）
  ├─ 主卡·对比卡：墨带多模型并置 + 结论行 + 五场景名次对比条 + 雷达叠加 + 多列名次清单
  ├─ 副卡·能力档案卡（每模型一张）：大字模型名 + 综合分 + 五场景名次 + 雷达/清单(±σ) + 强项/待加强 + 二维码
  ├─ 选人规则：单选 = 自动补当前场景第 1 名；未选 = Top 3
  └─ 输出三通道：
      发笔记    writeTempFile(多图) → postNote(image_resources ≤18, title≤20, content≤1000)
      发评论    interactionOpenApi(9.49+)：media_bean=本地路径 + miniToolSnapshotInfo(scene/scope/models ≤2KB)
                → 评论区重开工具恢复该次对比（引流闭环）；版本不足降级 toast
      存相册    saveImageToPhotosAlbum 循环保存
约束：成功回调 ≠ 已发布（toast 不得写「已发布」）；浏览器预览无 window.xhs 时按钮降级 toast
```

改版纪律：**分享卡改版要整块重写构图，不做参数微调**；构图必须原创，维度标签用书面短名。

### 5.5 状态记忆与深链

- `syncHash`：state 变更写回 URL hash（scene/scope/model/view…）；`readHash`：鲜载解析。
- 记忆 key `radar-state-v1`（scene/scope/selected/hidePending）：平台 `setStorage`（9.46+）优先、localStorage 兜底、读写失败静默。
- 规则：**深链优先、记忆只补缺；`scope=inf` 永不从记忆恢复**（防绕过门控）。

## 6. 平台 API 封装层（④层）清单

| API | 门槛 | 封装要求 |
|---|---|---|
| `getFollowStatus` / `followAuthor` | 9.51+ | resolve(-1) 必须复查；错误码 20002/15404 映射 toast；busy 防重 |
| `getLaunchOptions` | — | 同步值缺失 → 异步回退；只读同步会误判旧客户端 |
| `setStorage` / `getStorage` | 9.46+ | localStorage 兜底；失败静默 |
| `writeTempFile` / `postNote` / `saveImageToPhotosAlbum` / `interactionOpenApi` | 9.49+（评论） | 存在性检查 + catch → 降级 toast |
| 震动 | — | 存在性检查 + try/catch |

统一模式：**「存在性检查 → try/catch → 失败降级（放行/toast），绝不抛到全局」**。任何新 API 接入照此模板。

## 7. 视觉与信息设计（现状基线，可整体替换）

- **色彩**：墨 `#17160F`（刊头带）/ 米白纸 `#F4F1E8`（主体）/ 朱红（信号与名次章）；数据三色 = 朱红 / 蓝 / 绿的深化版（一种颜色 = 一个选中模型）。
- **形**：双线细框面板（品牌刊物语言）；无圆角卡片堆砌。
- **字**：Geist / Geist Mono（woff2 子集随包）；数字用无衬线统一字重区分优劣（衬线实验已被否决）。
- **安全区（必须保留的规则）**：容器全屏渲染下 Android `env(safe-area-inset-top)` 返回 0——所有顶栏/tabbar 的 env 规则必须保持「**固定基线在前（顶部 28px）、env 增强在后**」的双层写法。
- **文案分层**：应用内可用白话别名（动脑子/少瞎编…）做引导；对外物料（分享卡/发笔记）只用书面短名与信达雅文案；署名「赛博摆渡人」。

UI 重设计时：视觉层（本节）可自由重做；§5.3/§5.5 与 §8 的语义与平台规则**不可动**。

## 8. 构建与发布流程

```bash
pip install -r requirements.txt        # Python 3.12+（pandas）
python build.py                        # ① 主版：改数据后先跑（本版账本来自它的数据区）
python scripts/build_xhs.py            # ② 出包：dist-xhs/ + 根目录 model-radar-xhs.zip
python .skill/minitool-zip-builder/scripts/audit_artifact.py model-radar-xhs.zip   # ③ 必须 PASS
python scripts/preview_xhs.py          # ④ 本地预览 http://127.0.0.1:8642（必须 no-store）
                                       #    ?lock=1 强制锁定态预览；?lock=0 解除
```

- **预览注意**：不用裸 `http.server`（无缓存头会让旧 app.js 假装「改了没生效」）；浏览器预览无 `window.xhs`，门控默认放行。
- **发布**：zip 由维护者上传小红书创服平台。发布前完成真机三步验证（模拟器 → Android → iOS），未验证项不得声称已验证。
- **平台规则**：容器能力与 JSAPI 契约以小红书小工具**在线文档为准**（本地 skill 内 references 只是冻结基线）；动手前先查、有新增能力先播报再决定用不用。

## 9. 设计决策记录（为什么是现在这样）

| 决策 | 理由 |
|---|---|
| 关注门控只锁三处，核心免费 | 工具价值先行；锁多了伤体验，锁少了无引流。搜索不受前 10 限制——定向查找不是浏览全部 |
| API 失败一律放行（降级不误伤） | 门控是增长手段，不是功能前提；宁可不锁，不可误锁 |
| `scope=inf` 永不从记忆恢复 | 堵住「先解锁→记忆残留→换未关注设备/清状态后仍带 inf」的绕过路径 |
| 深链优先、记忆补缺 | 分享/回流场景要求 URL 语义稳定；记忆只服务无深链的普通回访 |
| 分享卡主语是「对比」 | 产品围绕能力对比展开；单模型评分卡偏离项目意义（历史两版因此被否） |
| 默认只展示前 10 | 手机屏密度 + 门控钩子；数据全量 33 随包内置，解锁即展开 |
| 置信带 ±σ + ≈平判定 | 位次分池内相对语义下，分差小不应下结论；支撑弱的对比自动放宽判平阈值 |
| 前端不重算分数 | 口径唯一出处是管线；页面只选口径，保证两版数字逐位一致、可对账 |
| 页脚二维码自绘（构建期预生成矩阵） | 不引第三方 JS（离线/CSP）、不贴截图（模糊）；载荷用主页短链实现扫码直达 |

## 10. 已知坑（实现时必读）

1. **删函数先 grep 全部调用点**（函数名本身，不是当初的业务关键词）——启动链死过整页。
2. **`followAuthor` 失败也 resolve(-1)**，不 reject；只处理成功值会让「点关注没反应」。
3. **`getLaunchOptions` 同步值在部分真机缺失**，必须两级读取，否则误判旧客户端而整体放行（门控失效）。
4. **mock 与真机落差**：mock 必须覆盖真机会走到的全部 API 面，否则本地通过、真机爆炸（两次教训）。
5. **预览服务器必须 no-store**，否则旧脚本缓存制造「改了没生效」假象。
6. **老内核 CSS**：`flex gap` 探针、`grid-gap` 别名、安全区双层写法，均不可省。
7. **平台规则会变**：本文档的平台约束是快照；每次动手前以在线文档为准核对。
