# 加模型 / 补数据指南

本文说明如何把一个新模型、或一条新证据，正确地加进项目。原则只有一句：

> **先找证据，再填表；宁可待定，不要硬凑。**

开始前请先读 [方法论](methodology.md) 的“基准族”“位次分”“三档口径”三节。

## 1. 三种常见场景

### 场景 A：全新模型，公开榜单有分

需要动 3–4 张表：`models.csv`、`raw_*.csv`、`canon.csv`，必要时 `mapping.csv`。

### 场景 B：已有模型的新版本

例如 `DeepSeek-V4.1-Flash` 的 0910 版与 1017 版。

**新版本单列一册**，不要覆盖旧版本：

- `models.csv` 新增一行（名称带版本/日期）；
- `raw_*.csv` 用新模型名新增证据；
- `canon.csv` 把榜单上的新版本名映射到新统一名；
- 旧版本继续保留，便于比较升级是否真的发生。

### 场景 C：匿名/无公开数据的模型

例如 stealth 模型、刚发布但没有任何 benchmark 的模型。

只在 `models.csv` 加一行占位：

- `开源` 写 `未确认`（如果有明确证据才写是/否）；
- `备注` 写明“无公开可核 benchmark”；
- **不要**编造分数，也不要用推理值假装实测；
- 页面会把它显示为“待定”。

## 2. 六张表各写什么

| 表 | 作用 | 什么时候动 |
|---|---|---|
| `data/models.csv` | 模型名册：公司、开源、数据日期、备注 | 每次加模型 |
| `data/raw_*.csv` | 原始证据：来源、类别、原始分、量纲、日期、URL | 每次加证据 |
| `data/canon.csv` | 榜单模型名 → 统一名 | 榜单名与统一名不同时 |
| `data/mapping.csv` |（来源, 类别）→ 维度 + 基准族 | 出现新来源/新类别时 |
| `data/dimensions.csv` | 8 维定义、白话、典型任务 | 只有新增维度/改定义时（很少） |
| `data/weights.csv` | 5 套场景 × 8 维相对权重 | 只有新增场景/调权重时（很少） |
| `data/scores.csv` | **生成物**，不要手改 | 不直接编辑 |

## 3. 场景 A 的完整步骤

### Step 1：在 `models.csv` 加名册行

```csv
模型,公司,开源,数据日期,备注
Example-Model-1.0,Example Inc,是,2026-10-21,Example 系列旗舰；1M 上下文；公开权重；来源见 raw
```

字段说明：

- `模型`：项目统一名，后续所有表都用它；
- `公司`：厂商名；留空时会尝试从 raw 的 `公司` 列反查；
- `开源`：`是` / `否` / `未确认`；判定标准是**权重是否可公开下载**；
- `数据日期`：该模型发布/数据快照日期，不是今天；
- `备注`：上下文、参数、已知缺口、TB 版本差异等，会显示在证据抽屉与悬停提示。

### Step 2：在 `raw_*.csv` 加证据行

如果来源已有 raw 文件，直接追加；如果是新来源，新建 `data/raw_<source>.csv`。

列必须为：

```csv
模型,公司,来源,类别,原始分,量纲,数据日期,URL
```

示例：

```csv
Example-Model-1.0,Example Inc,Artificial-Analysis,GPQA,0.812,0-1,2026-10-21,https://artificialanalysis.ai/models/example-model
```

字段说明：

- `模型`：**榜单上的原名**，不是统一名；由 `canon.csv` 负责转换；
- `来源`：稳定、可读的来源名，例如 `Artificial-Analysis`、`LiveBench-2.0`、`SuperCLUE`；
- `类别`：来源内部的基准/类目名，必须与 `mapping.csv` 的 `类别` 完全一致；
- `原始分`：照抄来源，不要先归一化；
- `量纲`：`0-100` / `百分制` / `0-1` / `0-1越低越好` / `10分制` / `5分制` / `Elo` / `指数`；
- `数据日期`：来源页面标注的日期，不是抓取日；
- `URL`：能回到该条证据的页面；一个模型页对应多条证据时，每行都写。

**不要**把多个版本、多个设置的分混在同一行；一行只表达一个（模型, 来源, 类别, 日期）的证据。

### Step 3：在 `canon.csv` 加别名

```csv
榜单名,统一名,备注
Example Model 1.0 (High),Example-Model-1.0,AA 显示名
example-model-1.0,Example-Model-1.0,LiveBench 模型键
```

规则：

- `榜单名` 必须与 raw 里的 `模型` 完全一致（含空格、括号、大小写）；
- 一个榜单名只能映射到一个统一名；
- 如果 raw 里已经是统一名，可以不加别名；
- 加完可以用 `grep` 检查 raw 里是否还有未命中的名字。

### Step 4：必要时改 `mapping.csv`

只有当**来源或类别是新的**时才需要加行：

```csv
来源,类别,维度,族,备注
Artificial-Analysis,GPQA,推理与知识,AA·GPQA,AA 的 GPQA Diamond
```

规则：

- `维度` 必须是 `dimensions.csv` 里的 8 个之一；
- `族` 是基准族名。**同一基准的不同报法用同一个族名**；不同基准不要为了“凑人数”并族；
- 总分/综合指数如果不打算映射，`维度` 留空，明确声明“有意不映射”；
- 新族名一旦引入，检查池内是否有至少 4 个模型；不足 4 人不会计分，但仍可留档。

### Step 5：重建账本并检查诊断

```bash
python build_scores.py
```

重点看输出：

- 是否提示“既未映射、也未声明有意不映射”；
- 基准族去重删了哪些行；
- 计分族/未计分族数量是否符合预期；
- 新模型的证据是否进入 `scores.csv`。

然后检查：

```bash
grep "Example-Model-1.0" data/scores.csv
```

确认：

- 每个（模型 × 族）只有一票；
- `族内n` 是否正确；
- 没有把旧版本/竞品分混进来。

### Step 6：重建页面

```bash
python build_html.py
```

`build_html.py` 会整体覆盖 `model-radar.html` 的数据区。打开页面确认：

- 模型能搜索到、能选中；
- 雷达 / 条形图有该模型；
- 证据抽屉的族、n、原始分与日期正确；raw 行的 URL 可回源；
- 缺失维显示“待定”，不是 0；
- 切换三档口径没有异常。

### Step 7：校验

```bash
python scripts/validate.py
```

必须通过。若失败，按错误提示修表；不要用改校验脚本的方式“绕过”。

### Step 8：更新 CHANGELOG，提交 PR

在 `CHANGELOG.md` 的 `[Unreleased]` 下写：

- 新增了哪个模型/来源/证据；
- 数据日期；
- 对覆盖、族数、榜位的影响；
- 已知缺口（哪些维仍待定）。

PR 请同时包含：

- `data/` 下的表；
- `model-radar.html`（如果跑过 `build_html.py`）；
- `CHANGELOG.md`；
- 证据截图或原始页面链接（方便 review）。

## 4. 场景 B：新版本怎么处理

### 4.1 单列，不覆盖

新版本是一个新的模型实体：

- `models.csv` 新增一行：`Example-Model-1.1`；
- `canon.csv` 把榜单上的 `Example Model 1.1` 映射到新名；
- `raw_*.csv` 用新名追加证据；
- 旧版本 `Example-Model-1.0` 继续保留。

不要用“最新版覆盖旧版”的方式改 raw，否则历史分数会消失，也无法比较升级是否真的发生。

### 4.2 同族与不同族

- 同一 benchmark 的不同版本（如 TB4.0 / TB2.1）通常同族，按项目规则去重；
- 不同题目集/不同代际的 benchmark（如 LiveBench 1.x / 2.0）**不并族**；
- 同一模型家族的新旧版本是**不同模型**，各自在族内占一票。

### 4.3 版本对不上就不收

如果榜单只写 `Example Model`，没有版本/日期，而项目里有 1.0 与 1.1 两版：

- 能通过发布日期、参数、官方页面锁定版本 → 收；
- 锁不定 → 不收，或只在备注里记“版本不明”；
- 不要用“应该是新版”做猜测。

## 5. 场景 C：待定模型怎么占位

```csv
模型,公司,开源,数据日期,备注
Space-Bunny,匿名,未确认,2026-09-23,匿名 stealth 预览模型；无公开可核 benchmark；8 维暂无证据
```

- `开源` 写 `未确认`；
- 不建 raw 行；
- 不写推理值（除非有明确的方法与依据，且默认不计分）；
- 页面显示“待定”，不参与综合分。

## 6. 数据纪律（PR 会被按这些检查）

1. **没有来源不入账。** 每行必须有 URL 与数据日期。
2. **不伪造分数。** 不把“看起来差不多”的竞品分抄给新模型。
3. **厂商自报只用于该厂商自己的模型。** NVIDIA 官方页给非自家模型报的分，不能当成那个模型的第三方证据；在“仅第三方”口径下会被整体排除。
4. **精确版本。** 版本/日期/设置对不上，宁可不收。
5. **同一基准一票。** 同（模型 × 族）多来源时，第三方优先、日期新者优先；被淘汰行留 raw。
6. **族内 <4 不计分。** 不要为了“让某模型有分”而把不同基准硬并成一个族。
7. **缺数据 ≠ 0。** 缺失维保持空白；不要用 0 占位。
8. **推理值默认不计分。** 只放 `raw_inferred.csv`，写清方法、依据、LOO MAE；页面默认不纳入。
9. **价格 / 套餐不进雷达轴。** 雷达只画能力；这类信息变动太快，放进图里会立刻过期。
10. **删模型要清干净。** `models.csv`、所有 raw、`canon.csv` 里的相关行一起清理，否则会出现“幻影模型”。

## 7. 常见错误

| 错误 | 后果 | 修法 |
|---|---|---|
| raw 用了榜单原名，但 canon 没加别名 | `scores.csv` 里出现两个模型，或旧模型残留 | 补 canon，重建 |
| 新类别没进 mapping | 该行被静默丢弃，页面少证据 | 补 mapping，或声明有意不映射 |
| 把 TB2.1 和 TB4.0 都计分 | Agent 维双重计权 | 项目自动优先 TB4.0；确认 raw 留档即可 |
| 把厂商自报当第三方 | “仅第三方”口径被污染 | 来源名加入 `VENDOR_SRC` |
| 新版本覆盖旧版本 | 历史分数消失，无法比较升级 | 新版本单列一册 |
| 删模型只删 models.csv | raw 残留继续计分，出现幻影模型 | 清 raw + canon |
| 为了凑 n=4 把不同基准并族 | 分数失真，不可比 | 保持独立族，等真实证据 |
| 手改 `scores.csv` | 下次构建被覆盖 | 改 raw/mapping/canon，重建 |

## 8. PR 检查清单

- [ ] `models.csv` 有该模型，名称与所有表一致；
- [ ] 每条 raw 行有来源、类别、原始分、量纲、数据日期、URL；
- [ ] `canon.csv` 覆盖所有榜单原名；
- [ ] 新来源/类别在 `mapping.csv` 有映射或“有意不映射”声明；
- [ ] 没有为了凑人数而并族；
- [ ] `python build_scores.py` 无未映射警告；
- [ ] `data/scores.csv` 已重建并提交；
- [ ] `python build_html.py` 已运行，页面可选中新模型；
- [ ] `python scripts/validate.py` 通过；
- [ ] `CHANGELOG.md` 已更新；
- [ ] PR 描述附原始来源链接/截图。

如果你不确定某个基准该归到哪个族，先在 Issue 里贴出基准说明、题目类型和现有成员，讨论清楚再改表。归族是判断，不是抄一个名字。
