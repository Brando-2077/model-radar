# 常见问题（FAQ）

## 分数与口径

### 为什么页面上的分数和官方 benchmark 不一样？

官方的 0–100 是“在这套题上答对/得分多少”；本项目的 0–100 是“在同一个基准族的模型池里，赢过多少比例的对手”。

两者回答的不是同一个问题。一个模型官方 85 分，可能在本池里只排中游；另一个官方 70 分，可能在本池里排前列。页面抽屉会同时给出原始分、族内人数和位次分，方便对照。

### “90 分”是准确率 90% 吗？

不是。它表示在该基准族的模型池里，大约赢过 90% 的对手。n 越大越接近 0–100 两端；n=4 时四档约为 12.5 / 37.5 / 62.5 / 87.5。

### 为什么我加了一个新模型，所有模型的分数都变了？

因为位次分是**池内相对分**。池子里多一个强模型，其他人的名次可能整体后移；多一个弱模型，其他人可能整体前移。这是相对排名的性质，不是 bug。

跨期比较请看相对名次、覆盖度和证据变化，不要逐格比较绝对分数。

### 为什么某维显示“待定”，而不是 0 分？

因为“没有证据”和“能力为 0”是两件事。项目把缺失维从雷达断开、从综合分权重中让位，而不是画到圆心或按 0 分处理。

如果某维只被厂商自报覆盖，切到“仅第三方榜单”后也会变成“待定”。这是有意的：宁可承认不知道，也不拿单一渠道的分冒充第三方证据。

### 为什么族内少于 4 个模型不计分？

n=2 时位次分只有 25 / 75 两档，n=3 时只有 16.7 / 50 / 83.3 三档，分辨率太粗，容易被误读成真实能力差距。4 是一个固定门槛，在覆盖率和可读性之间折中。

不足 4 人的证据仍保留在账本里，等池子变大后自动参与。

### “†”是什么意思？

某模型某维只有 1 个计分基准族支撑时，页面加 †。它提醒你：这一维只有单一来源，不等于模型弱，也不等于结论稳。

点开证据抽屉可以看到具体是哪个族、池内多少人。

### 为什么有三个数据口径？

- **全部来源**：所有证据都参与，包括厂商自报。
- **仅第三方榜单**：整体排除厂商自报渠道，看更独立的证据。
- **含推理补全**：在全部来源基础上，把缺失格的推理估计值显示出来；默认不计分。

三个口径不是三套分数，而是三种“看哪些证据”的选择。页面只切换口径，不重算位次分。

### 为什么厂商自报要单独排除？

厂商自报可能选择有利的设置、采样温度或版本，也可能只公布赢的基准。项目不假设厂商一定不诚实，但认为它和第三方证据的可比性不同，所以给用户一个一键排除的选项。

排除按**渠道**，不按“是不是自家模型”：NVIDIA 官方页给别家模型报的分，也会一起被排除。

## 模型与数据

### 为什么有的模型 8/8，有的只有 2/8？

因为公开证据覆盖不同。有的模型刚发布、只有厂商模型卡；有的模型没有被中文/人评榜单收录；纯文本模型在“图片与制图”维是结构性缺失。

覆盖少不代表模型弱，但综合分的可比性会下降。页面用 `n/8`、† 和“低覆盖”提示暴露这一点。

### 为什么没有价格、速度、套餐？

这是项目的范围选择。价格、速度、隐私、部署方式、供应商稳定性都重要，但它们不是“能力维度”，而且套餐/价格变动频繁、地区差异大。

本项目只回答“公开证据范围内的能力画像”，不把价格塞进雷达轴，也不做购买导流。需要性价比时，请结合自己的账单和延迟实测。

### 为什么不做一个唯一的总榜？

因为“最强”依赖任务。写代码、做 RAG、写文案、跑 Agent 的最优权重不同。项目提供 5 套场景权重，并允许你看单维分数；综合分只是某个场景下的一种取舍。

### 为什么不用所有公开 benchmark？

因为不是所有 benchmark 都满足：公开可访问、能对应到精确模型版本、有可复核的原始分、能归入稳定的基准族。项目宁可少收，也不把不可比的分硬拼在一起。

### 为什么中文写作的分数看起来很少？

中文写作的公开、可核、精确同款数据仍然很少。SuperCLUE-Writing 当前只有少量模型；AIWB 是英文口径。项目不会用英文写作分去冒充中文写作分。

### 数据多久更新一次？

不定期，靠人工采集与 PR。每个 raw 行都有数据日期和 URL；页面有构建日期。它不是实时榜单。

### 可以商用吗？

代码是 MIT；本项目整理的数据与文档是 CC BY 4.0，允许商用，但必须署名、附许可链接、说明修改，且不得暗示背书。

上游榜单/模型卡的数据版权归原发布方，使用前请阅读他们的条款。详见 [DATA_LICENSE.md](../DATA_LICENSE.md)。

## 纠错与贡献

### 发现分数抄错/版本对不上，怎么报？

开一个 **Data correction** Issue，附：

- 模型与维度；
- 当前页面/账本里的值；
- 你认为正确的值；
- 原始来源 URL、数据日期、截图或原文；
- 版本/设置说明。

最有效的纠错不是“这个分看起来不对”，而是“这条原始证据在这里，当前账本漏了/抄错了”。

### 可以加自己喜欢的模型吗？

可以。先读 [加模型指南](adding-models.md)，按表填写并跑校验。只要证据可复核、版本能对上、没有为了凑人数而并族，就欢迎。

### 为什么我的 PR 被要求删掉一些行？

常见原因：版本对不上、来源不可复核、厂商自报被当成第三方、为了凑 n=4 硬并族、删模型时 raw 残留、或手改了 `scores.csv`。PR 模板里有检查清单。

### 页面打不开/图表不显示怎么办？

- 确认打开的是 `model-radar.html`，不是只下载了数据文件；
- 用近两年的 Chrome / Edge / Firefox / Safari；
- 打开浏览器控制台看是否有报错；
- 如果是自己改过壳，先跑 `python build_html.py` 恢复数据区，再检查改动。

仍无法解决，请开 **Bug report**，附浏览器版本、操作步骤、控制台报错和截图。
