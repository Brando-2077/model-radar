## 1. 先看结论

如果只记十句话：

1. **分数不是绝对能力值，是“当期模型池内的相对位次”。** 每个基准先归入一个「基准族」，族内按原始分排名，再换算成“赢过了池内多少比例的对手”（0–100）。
2. **同一基准跨来源只算一票。** 例如 AA 和厂商模型卡都报了 HLE，只会留下一条（第三方优先、日期新者优先）。
3. **小族降权入分（v0.26 起）。** 族内 ≥4 全权、3 个 ×0.6、2 个 ×0.35；仅 1 个模型的族不计分（单模型无对手，证据保留可查）。
4. **维度分 = 该维各计分族位次分的算术平均。** 不按样本数加权，也不按来源摊权——一个族就是一票。
5. **场景综合分 = 有分维度的加权平均。** 缺数据的维度不按 0 算，而是把它的权重让给其他维度（再归一化）。
6. **缺数据 ≠ 0。** 雷达断开、条形留斜纹空位、矩阵斜纹、轴端空心圈；任何“塌向圆心”的画法都是回归。
7. **三档口径只决定“哪些证据进入平均”，不重算位次。** 全部来源 / 仅第三方榜单 / 含推理补全。
8. **厂商自报按渠道整体排除。** 判断依据是来源渠道，不是“是不是自家模型”。
9. **推理补全是显式标注的估计值，默认不计分。** 只在第三档口径显示，且只补**没有任何计分实测**的格子；若某格只有“样本不足”的实测证据（族内 n<4），推理值也会补位，但那条实测仍保留在抽屉里。
10. **所有数字都能回到一条带来源与数据日期的证据。** 实测行的 URL 在 `raw_*.csv`，推理值的 URL 在 `raw_inferred.csv`；页面的证据抽屉展示来源、原始分、日期、族与池大小，推理行额外展示方法/依据/MAE/URL。

## 2. 项目目标与不做什么

### 2.1 目标

为「按场景选模型」做决策可视化：

- 把公开榜单的异构分数，归一到 **8 个能力维度**；
- 按 **5 套真实任务场景** 的权重，算出一个可比较的综合分；
- 产出**单文件、零依赖、双击即开**的 `model-radar.html`；
- 每个分数都能下钻到证据：来源、类别、原始分、量纲、数据日期、族内池大小；推理值还会显示方法、依据、MAE 与 URL。实测行的 URL 保留在对应的 `raw_*.csv` 里。

### 2.2 明确不做

| 不做 | 原因 |
|---|---|
| 速度 / 价格 / 性价比进雷达轴 | 套餐与价格变动频繁，且与“能力”不是同一坐标系 |
| 媒体主观分、自测分 | 2026-10-17 取消；只保留可核的公开跑分与榜单 |
| 未加权均值表盘 | 场景权重是这个项目的核心表达 |
| 把缺失维按 0 画 | 会把“没考”误读成“考砸”，是设计红线 |
| 页面内手工编辑 / 导入导出 | 数据更新统一走 `data/` + 构建脚本 |
| 实时榜单 | 人工采集 + PR；每条证据带数据日期 |
| 用 OpenRouter 用量热度扩雷达轴 | 热度 ≠ 能力；如要做只能放在图外 |

## 3. 一条证据的完整旅程

以「DeepSeek-V4.1-Flash-1017 的 HLE 分数」为例：

```
① 采集      data/raw_aa_lmarena.csv
            模型=DeepSeek-V4.1-Flash-1017, 来源=Artificial-Analysis,
            类别=HLE, 原始分=0.433272, 量纲=0-1,
            数据日期=2026-10-20, URL=https://artificialanalysis.ai/models/...

② 命名统一  data/canon.csv    榜单名 → 统一名
③ 维度+族   data/mapping.csv (来源, 类别) → 维度=推理与知识, 族=HLE

④ 归一化    build_scores.normalize()
            0-1 → ×100 = 43.3（面值，只用于族内排名）

⑤ 族去重    apply_family_scores()
            同一（模型 × HLE）只留一票 → 厂商自报那条被第三方淘汰

⑥ 位次分    族内 n=29，按面值升序排到第 17 名
            (17 − 0.5) / 29 × 100 ≈ 56.9（1 位小数）

⑦ 写账本    data/scores.csv
            模型,维度,榜单分,备注,族,族内n

⑧ 维度分    build_html.blend_models()
            该模型「推理与知识」下所有计分族位次分的算术平均

⑨ 页面      model-radar.html 数据区
            evidence[] 一条明细 + models[].scores["推理与知识"]
```

关键点：

- **归一化只保证“同一族内可以排名”**，不保证跨族可比；跨族可比是靠“位次分”这一步。
- **族内排名用的是面值**，但 min-max / ×100 都是单调变换，不改变名次。
- **写进 `scores.csv` 的「榜单分」已经是位次分**（计分族），不再是原始面值；原始面值仍保留在 `备注` 字符串里。

## 6. 五套场景权重与综合分

### 6.1 原始权重

`data/weights.csv` 是 40 行（5 场景 × 8 维）的原始权重，构建时按场景归一化到合计 100.0。

**归一化用最大余数法**（`build_html.load_scenarios()`）：先按比例算精确值，再向下取整到 0.1，最后把剩余 0.1 依次补给小数部分最大的维度。这样每套场景合计**恰好 100.0**，不会出现 99.9 / 100.1。

| 自媒体内容运营 | 9.1 | 2.7 | 18.2 | 9.1 | 10.9 | 13.6 | **27.3** | 9.1 | 100.0 |

### 6.3 综合分公式

页面里的 `composite(m, scene)`：

```
综合分 = Σ_{d ∈ 有分维度} w_d × s_d  /  Σ_{d ∈ 有分维度} w_d
```

- `s_d` 是该模型在当前口径下第 d 维的分数（0–100）。
- **缺分维度不进入分子，也不进入分母**——等价于把它的权重按比例让给其他维度。
- 因此综合分仍然是 0–100，但“覆盖越少，分数越只代表已考的部分”。

### 6.4 覆盖度与低覆盖提示

| 概念 | 代码 | 含义 |
|---|---|---|
| 维度覆盖 | `coverage(m)` = 当前口径下有分维度个数 | 榜行显示 `n/8` |
| 权重覆盖 | `wCov / wTot` | 本场景下“有分维度的权重和 / 全部权重和” |
| 低覆盖 | `LOW_COV = 0.6` | 权重覆盖 <60% → 榜行标「·低覆盖」，tooltip 写明“名次仅供参考” |

低覆盖**不乘惩罚系数**——那会与“缺数据让权”的红线冲突。它只是显式标注，把判断权交还读者。

### 6.5 排名与「≈平」

- 榜单按综合分**降序**排列；`ranked()` 过滤掉 0 覆盖（待定）模型。
- 同分不设并列名次：稳定排序后按模型名顺序依次占位。
- 逐维对照 / 场景取舍里用 `TIE = 2`：两个候选差 **<2 分** 视为噪声级，标「≈平」，不判胜负。
- 结论条里的“领先/胜出”也遵守 ≥2 分才判胜负的口径。

## 8. 原始证据表与采集纪律

### 8.1 `raw_*.csv` 的固定 schema

所有 `raw_*.csv`（除 `raw_inferred.csv`）都是 8 列：

| 列 | 必填 | 说明 |
|---|---|---|
| `模型` | 是 | 榜单原名；必须在 `canon.csv` 或 `models.csv` 中能解析到统一名 |
| `公司` | 否 | 仅用于反查厂商；统一名以 `models.csv` 为准 |
| `来源` | 是 | 渠道名；必须在 `mapping.csv` 中声明 |
| `类别` | 是 | 榜单的具体指标/子榜；与 `来源` 组成唯一键 |
| `原始分` | 是 | 数字；**保留上游原值**，不做任何预先折算 |
| `量纲` | 是 | `0-100` / `百分制` / `0-1` / `0-1越低越好` / `10分制` / `5分制` / `Elo` / `指数` |
| `数据日期` | 是 | 来源页面标注的日期，不是抓取日期；允许 `YYYY-MM` |
| `URL` | 是 | `http(s)`；能回到该条证据的页面 |

### 8.2 采集纪律

1. **先有来源，再有分数。** 没有 URL 或数据日期的行不入账。
2. **精确版本。** 模型名、版本号、日期、设置至少有一项能锁定同一版本；对不上就不收，不做“同系列近似”。
3. **不改上游原值。** 折算只在 `build_scores.py` 里发生。
4. **不静默补值。** 缺失保持空白；推理值只进 `raw_inferred.csv`，默认不计分。
5. **同一基准一票。** 同（模型 × 族）多来源时，第三方优先、日期新者优先。
6. **池内模型优先。** 非本项目名册的模型不为“凑人数”而入账。
7. **删模型要清残留。** raw / canon / mapping / models 四处一起清，避免“幻影模型”继续计分。

### 8.3 `raw_inferred.csv` 的 schema（另一条通道）

| 列 | 说明 |
|---|---|
| `模型` | 统一名，必须在 `models.csv` |
| `维度` | 8 维之一 |
| `推理分` | 0–100 位次分 |
| `推理方法` | `M1 同族前版直推` / `M2 池内k近邻(...)` |
| `依据` | 方法、样本、MAE、来源说明 |
| `留一MAE` | 该维留一验证 MAE |
| `数据日期` | 推理快照日期 |
| `URL` | 依据来源 |

这张表**列结构与 raw 不同**，所以 `build_scores.py` 单独读、单独出账，来源一律记「推理补全」。

## 11. 第一步归一化：把不同量纲折成 0–100

代码：`build_scores.normalize(v, scale, pool)`。

| 原始量纲 | 折算 | 当前是否使用 |
|---|---|---|
| `0-100` / `百分制` | 原值 | 是 |
| `0-1` | `v × 100` | 是 |
| `10分制` | `v × 10` | 是 |
| `5分制` | `v × 20` | 是（当前无行） |
| `Elo` / `指数` | 池内 min–max 线性映射到 **60–100** | 是 |
| `0-1越低越好` | **代码未实现反转** | **否，有意不映射** |

### 11.1 Elo / 指数的池内映射

```
lo, hi = min(pool), max(pool)
面值 = 60 + (v − lo) / (hi − lo) × 40      # hi == lo 时取 80
```

- `pool` 是**同一（来源, 类别）分组内的全部原始值**，不是全库、也不是族。
- 这是单调变换：同一组内不改变谁高谁低，只把量纲拉到 60–100。
- 真正的跨基准比较发生在下一步「族内位次分」。

### 11.2 为什么 `0-1越低越好` 不实现

AA 的 `AA-Omniscience Hallucination Rate` 是“越低越好”。项目**有意不映射**它：

- 若直接 ×100，会把“幻觉率最低”变成“分数最低”，方向反了；
- 若反转 `(1−x)×100`，需要先确认该字段的刻度定义与缺失值处理；
- 当前代码没有这个分支，误映射会直接抛 `ValueError`（这是有意的“硬失败”，防止静默算错）。

**结论：该类别保持不映射；如果未来要接入，先在 `normalize()` 里补反转实现，再加 mapping 行并重跑全链路。**

### 11.3 舍入

- 归一化后面值 `round(..., 1)` 写进账本。
- 位次分同样 `round(..., 1)`。
- 页面展示的维度分与综合分也是 1 位小数；因此不同步骤的四舍五入可能带来 ±0.1 的显示差，这是预期噪声。

## 12. 第二步基准族：同一把尺子只算一票

### 12.1 什么是基准族

「族」= **同一个基准/同一套题的不同报法**。例如：

- AA 的 `HLE`、腾讯官方转录的 `HLE`、DeepSeek 官方模型卡的 `HLE` → 同一个族 `HLE`；
- AA 的 `Terminal-Bench 4.0` 与 `Terminal-Bench 2.1` 是**两个族**（`TB4.0` / `TB2.1`）；但 **AA 的**同一模型只取一版，避免双版本重复计权；
- LiveBench 1.x 的 `Coding` 与 LiveBench 2.0 的 `Coding` → **不同族**（`LB·Coding` / `LB2·Coding`），因为题目集不同。

族的粒度决定“什么算重复计权”。当前 87 个声明族、79 个有证据。

### 12.2 同（模型 × 族）只留一票

排序键（`apply_family_scores()`）：

```python
ordered = fam_rows.sort_values(["_vend", "_date"], ascending=[True, False])
kept = ordered.drop_duplicates(subset=["模型", "_fam"], keep="first")
```

- `_vend=False`（第三方）排在前面 → **第三方优先**；
- 同为第三方/厂商时，`_date` 降序 → **日期新者优先**；
- 被淘汰的行**不进 `scores.csv`**，但仍留在 raw 里可溯源。

当前只淘汰了 3 条（全部是 1017 的厂商自报，被 AA 第三方顶掉，见 §9.4）。

### 12.3 Terminal-Bench 特例

TB 的去重发生在族去重**之前**，且只看 AA 的 2.1 / 4.0：

- 有 AA TB4.0 的模型 → 丢弃其 **AA 的** TB2.1；
- 没有 AA TB4.0 的模型 → 保留其 TB2.1（AA 或其他渠道），归入 `TB2.1` 族。

当前 AA 的 17 条 TB2.1 **全部**因对应模型已有 AA TB4.0 而被丢弃；`TB2.1` 族只剩 3 条厂商证据（n=3），因此样本不足、不计分（见 §18.4）。被丢弃的行仍留 raw。

> 注意：这条规则**只作用于 AA 的 TB2.1**。厂商渠道的 TB2.1 行不受影响，所以同时有 AA TB4.0 和厂商 TB2.1 的模型（如 GLM-5.3）会在账本里保留两条 TB 证据、分属两个族；`TB2.1` 族 n=3 在 v0.26 后以 ×0.6 低置信权重入分。若未来该族继续长大，需要重新评估这条规则是否也要覆盖厂商行。

### 12.4 族内最小池 `FAMILY_MIN_N = 4`

族内模型数 <4 时**不计分**，但证据保留、写 `族` 与 `族内n`，页面标「样本不足」。

理由：位次分在 n 很小时分辨率失真——

| 族内 n | 最强者的位次分 | 最弱者的位次分 |
|---:|---:|---:|
| 2 | 75.0 | 25.0 |
| 3 | 83.3 | 16.7 |
| 4 | 87.5 | 12.5 |
| 29 | 98.3 | 1.7 |

n=2 时最强者也只有 75 分、最弱者 25 分，位次分被压缩在中间，分辨不出真实差距；n≥4 后曲线才相对稳定。——这正是 v0.26 给 n=2/3 低权重（×0.35/×0.6）的原因：数据可用，话语权按可信度分配。

### 12.5 样本不足的行怎么处理

- `scores.csv` 里 `榜单分` **保留归一化面值**（不是位次分），`族` / `族内n` 照写。
- `build_html.load_scores()` 用 `_scored = (~推理) & (族内n ≥ 2)` 过滤（v0.26）；n=2/3 行以 fam_weight 降权进入维度均值，n=1 行不进入。
- 页面抽屉会显示“样本不足不计分”，矩阵/条形按缺失处理。

## 13. 第三步族内位次分

代码：`apply_family_scores()`。

```python
kept["_pct"] = kept.groupby("_fam")["榜单分"].transform(
    lambda s: (s.rank(method="average") - 0.5) / len(s) * 100)
```

### 13.1 公式与方向

```
位次分 = (族内升序名次 − 0.5) / 族内模型数 n × 100
```

- `rank()` 默认 **升序**：原始分最低 = 第 1 名。
- 所以：**原始分越高 → 名次越大 → 位次分越高**。
- 最弱者 ≈ `0.5/n×100`（n=29 时约 1.7）；最强者 ≈ `(n−0.5)/n×100`（约 98.3）。
- 语义：**“在该基准的模型池里，赢过了多少比例的对手”**。

> 常见误读：把“第 1 名”理解成“最强”。这里第 1 名是**升序第一名 = 最低分**；最强者是第 n 名。抽屉里已明写“同族内分数越高＝赢过越多对手”。

### 13.2 并列

`rank(method="average")`：并列取平均名次。

例：n=4，两个模型并列最高 → 名次 3.5 → 位次分 `(3.5−0.5)/4×100 = 75.0`；另两个分别为 37.5 / 12.5。

### 13.3 为什么用位次而不是面值

不同基准的难度、量表、harness 都不同：HLE 40 分可能是顶尖，SuperCLUE 80 分可能只是中游。直接平均面值会让“容易的基准”主导维度分。

位次分把每个族压到同一把 0–100 的尺子上：**只看你在该族池子里的相对位置**。代价是：

- 分数是**池内相对分**，增减模型会整体移动；
- 跨期看图只能比相对位次，不能比绝对分；
- 小族（n 小）的位次分颗粒度粗，所以 v0.26 用降权（×0.6/×0.35）而非排除。

## 14. 第四步维度分

代码：`build_html.blend_models()`。

```python
vals = g2.loc[g2["_scored"], "榜单分"].dropna()
dims[dim] = round(float(vals.mean()), 1)
```

### 14.1 规则

- 维度分 = 该维**所有计分族**位次分的**算术平均**。
- 只算：非推理 + `族内n ≥ 2` + 有分数，按 fam_weight 加权。
- **不按族内 n 加权，也不按来源摊权**——一个族就是一票。
- 同一维有多少族，就最多有多少票；证据条数多不等于权重大。

### 14.2 真实例子：1017 的「推理与知识」

| 族 | 族内 n | 位次分 |
|---|---:|---:|
| `CritPt` | 29 | 74.1 |
| `HLE` | 29 | 56.9 |
| `LB2·Data Analysis` | 19 | 71.1 |
| `LB2·Reasoning` | 19 | 60.5 |

```
维度分 = (74.1 + 56.9 + 71.1 + 60.5) / 4 = 65.65 → 65.7
```

四个族权重相同；即使 `CritPt` / `HLE` 的池子更大，也不会多算。

### 14.3 单基准标记 `sf`

若某维的计分族**只有一个**，写 `sf = {维度: 族名}`，页面在该维加 `†` 小标，抽屉与 tooltip 写明族名。

真实例子：Claude-Opus-5.5 的「指令遵循」只有 `LB·IF (Instruction Following)` 一个族，位次分 38.2 → 维度分 38.2，标 `†`。

**单基准 ≠ 模型弱**，只表示“这一维目前只有一把尺子”。当前 `sf` 共 **81 格**（29 个模型），分布：

| 维度 | 单基准格数 |
|---|---:|
| 长文本 | 24 |
| 可靠性与低幻觉 | 22 |
| 指令遵循 | 14 |
| 内容创作 | 10 |
| 代码 | 5 |
| 图片与制图 | 4 |
| Agent与工具调用 | 2 |
| 推理与知识 | 0 |

### 14.4 为什么不用加权平均

- 按 n 加权会让“大池子的基准”压倒小池子，而池子大小是采集结果、不是重要性判断。
- 按来源摊权（曾经的 60/20/20）会把“同一能力的不同证据”变成“来源阵营投票”，已被取消。
- 算术平均最可解释：**这一维考了几个族，每个族一票。**

## 15. 第五步：场景综合分与排名（页面实现）

### 15.1 数据区里有什么

`build_html.py` 把账本写成 `window.RADAR_LEDGER`：

| 字段 | 内容 |
|---|---|
| `meta` | 版本、构建日期、来源说明、口径说明、缺失说明 |
| `dimensions[]` | 8 维定义 + 白话 + 典型任务 + 每维统计 `stats` |
| `scenarios[]` | 5 套场景 + 已归一到 100.0 的权重 |
| `models[]` | 每个模型的 `scores` / `scoresTp` / `scoresInf` / `sf` / `sfTp` / 公司 / 开源 / 备注 |
| `evidence[]` | 723 条逐条明细（来源、类别、原始分、量纲、日期、`val`、族、族内 n、厂商标记、推理标记）。`val` 的含义随行变化：计分行 = 位次分；样本不足行 = 归一化面值；推理行 = 推理分 |

### 15.2 页面只做三件事

1. **选口径**：`sv(m, d)` 按 `state.scope` 返回 `scores` / `scoresTp` / `scoresInf`。
2. **加权平均**：`composite()` 按当前场景权重算综合分，缺维让权。
3. **排序与展示**：`ranked()` 过滤 0 覆盖模型后按综合分降序。

**页面不重算位次分。** 所有 0–100 的维度分都是构建时算好的；切口径只是换一套已算好的数。

### 15.3 一个完整的综合分例子

Claude-Fable-5.1 在「自媒体内容运营」场景（8 维齐全，权重合计 100）：

| 维度 | 权重 | 维度分 | 加权贡献 |
|---|---:|---:|---:|
| 推理与知识 | 9.1 | 85.7 | 779.87 |
| 代码 | 2.7 | 92.4 | 249.48 |
| 指令遵循 | 18.2 | 75.7 | 1377.74 |
| Agent与工具调用 | 9.1 | 82.0 | 746.20 |
| 长文本 | 10.9 | 87.9 | 958.11 |
| 可靠性与低幻觉 | 13.6 | 92.9 | 1263.44 |
| 内容创作 | 27.3 | 82.5 | 2252.25 |
| 图片与制图 | 9.1 | 77.7 | 707.07 |
| **合计** | **100.0** | | **8334.16** |

```
综合分 = 8334.16 / 100.0 = 83.3416 → 83.3
```

### 15.4 缺维时怎么算

假设某模型只有 6 维有分，缺「内容创作」和「图片与制图」：

```
分母 = 100.0 − 27.3 − 9.1 = 63.6
综合分 = Σ(有分维度的 w×s) / 63.6
```

也就是把缺的两维权重按比例让给其余 6 维；同时榜行显示 `6/8`，若权重覆盖 <60% 再标「·低覆盖」。

### 15.5 排名细节

- 排序：`综合分降序`；0 覆盖模型不进入榜单。
- 同分：稳定排序，按模型名顺序占位（不设并列名次）。
- 结论条前三：`#1` 为主角，2/3 名作参照；首选理由取场景权重最高的两个有分维度。
- `TIE = 2`：两个候选差 <2 分标「≈平」，结论句不判胜负。
- 深链：`#scene=&model=&caliber=&scope=&view=&dim=`，刷新后恢复场景/模型/口径/图形/抽屉。

## 16. 三档数据口径

### 16.1 定义

| 口径 | `state.scope` | 进入维度均值的证据 | 页面数据 |
|---|---|---|---|
| 全部来源 | `all`（默认） | 所有**实测**计分行（含厂商自报，不含推理） | `scores` |

| 含推理补全 | `inf` | 计分实测优先；某格没有任何**计分**实测时用推理值 | `scoresInf`（仅在不同时写） |

### 16.2 厂商渠道 `VENDOR_SRC`

只有一处维护，`build_scores.py`：

### 16.6 推理值不会覆盖计分实测

`blend_models()` 的顺序是：

```python
real_all = 计分实测
infv = 推理值
if len(real_all): dims_inf[dim] = real_all.mean()
elif len(infv):   dims_inf[dim] = infv.iloc[0]
```

- **有计分实测就用计分实测**，哪怕只有一条。
- 推理值只在“该维一条计分实测都没有”时补位；只有样本不足实测（n<4）的格子也会用推理值补位，那条实测仍留在抽屉里。
- 校验器还会检查 `raw_inferred.csv` 不得覆盖已有计分实测的格子。

## 17. 推理补全：M1 / M2

### 17.1 定位

推理补全是**显式标注的估计值**，用于回答“如果一定要看这一格，最合理的猜测是多少”，但：

- 默认不计分；
- 只在「含推理补全」口径显示；
- 页面用虚线格 / 虚线框 / 空心顶点标识；
- 抽屉写明方法、依据、MAE、URL；
- **绝不能静默混进实测平均。**

### 17.2 M1：同族前版直推

适用：同一系列的新版本，官方模型卡给了新旧两版同表基准。

做法：

1. 取 1017 与 0910 官方同表的 11 项基准；
2. 只保留在本池能位次化的族（快照当时 6 项）；
3. 算两版位次分差的平均 `+14.9`，平均绝对差 `MAE 20.2`（2026-10-18 快照口径；换用今天的池子重算会不同）；
4. 对新版缺失维度：`前版维度分 + 14.9`，裁到 0–100。

当前状态：**0 条 M1**。1017 已补到 8/8 实测，不再需要 M1；代码保留，供未来同系列新版本使用。

### 17.3 M2：池内 k 近邻

适用：没有同系列前版、但池内还有其他模型的剖面可参考。

做法：

1. 用**已计分**的实测矩阵（快照时 214 个已知格）作为训练集；
2. 对目标模型的**已有维度剖面**，与池内其他模型算 **Pearson 剖面相似度**（只比“形状”，不比绝对水平；与邻居的共同维 ≥3 才算）；
3. 取相似度最高的 **k=5** 个邻居；
4. 对邻居在该维的位次分做**相似度加权平均**；
5. 只取正相似度邻居；没有邻居就放弃（宁缺勿假）。

选型不是拍脑袋：`infer_gaps.py` 会在同一批已知格上跑 **2 种相似度 × k∈{2,3,5}** 的留一验证，取 MAE 最低者。2026-10-18 快照上胜出的是 **Pearson + k=5，总体 MAE 21.5 位次分**。

### 17.4 留一验证（LOO）

- 把每个已知格依次“藏起来”；
- 目标格既不参与自己的剖面，也不作为邻居；
- 用其余格预测它，统计绝对误差；
- 214 个已知格 → 总体 MAE 21.5（2026-10-18 快照）；逐维 MAE：

| 维度 | MAE |
|---|---:|
| 内容创作 | 18.8 |
| 指令遵循 | 20.9 |

| 长文本 | 22.3 |

| 推理与知识 | 22.9 |

### 19.2 `validate.py` 到底查什么

| 层 | 检查 |
|---|---|
| 文件 | 必需文件存在、必需列齐全 |
| `dimensions.csv` | 恰好 8 行、维度名不重复、不为空 |
| `models.csv` | 模型名不重复、非空、开源列只允许 是/否/未确认（空值会警告并走公司兜底） |
| `weights.csv` | 恰好 5 套场景 × 8 维、维度不重复、权重非负、能归一化到 100.0 |
| `mapping.csv` | （来源, 类别）不重复、维度已知、维度与族同时为空或同时非空、一个族只属于一个维度 |
| `canon.csv` | 别名不重复、统一名必须在名册 |
| `raw_*.csv` | 模型/来源/类别非空、（来源,类别）已声明、原始分是数字、量纲已知、日期格式、URL 是 http(s)、模型能解析到名册 |
| `raw_inferred.csv` | （模型,维度）不重复、模型在名册、维度已知、推理分 0–100、方法/依据非空、URL、日期；**不得覆盖已有计分实测**；与 scores 的推理键一致 |
| `scores.csv` | 模型/维度已知、分数 0–100、推理行数一致、非推理行族不能为空、推理行不填族内n、族内n 是 ≥1 的数字、族/维度与 mapping 一致、无重复（模型,族） |
| HTML | 数据区标记存在、JSON 可解析、必需字段齐全、版本/日期格式、8 维/5 场景、模型名册一致、证据数/多重集/族信息/厂商标记一致、场景权重合计 100.0、待定模型不得有维度分 |

### 19.3 CI 做什么

`.github/workflows/validate.yml`：

1. `python -m py_compile build_scores.py build_html.py scripts/*.py`
2. `python build_scores.py`
3. `git diff --exit-code --ignore-cr-at-eol -- data/scores.csv`
4. `python scripts/validate.py`

第 3 步是关键：**账本必须与 raw 同步提交**。如果有人改了 raw 却没重建/提交 `scores.csv`，CI 会失败。

> CI 只重建账本，不重建 HTML——HTML 的数据区由贡献者在本地跑 `build_html.py` 更新。校验器会逐条比对 HTML 与 `scores.csv`，所以漏更新也会被抓到。

### 19.4 复现步骤

```bash
python -m pip install -r requirements.txt
python build_scores.py     # 期望：729 条证据 / 669 计分 / 44 族 / 234 格
python build_html.py       # 期望：数据区 729 条 evidence
python scripts/validate.py # 期望：0 错误 0 警告
```

### 19.5 幂等性

- `build_scores.py` 对同一份 raw 是确定性的：排序、去重、位次分都可复现。
- `build_html.py` 写入的 `meta.built` 是**运行当天**，所以跨日重跑 MD5 会变；同日内连跑应字节一致。
- 校验不比对 MD5，只比对内容结构，因此跨日构建不会被误判。

### 19.6 人工复核一个分数的步骤

1. 页面点该维度 → 打开证据抽屉；
2. 看每条证据的「族 · 池内 n · 位次分」；
3. 到 `data/scores.csv` 搜 `模型 + 维度`，确认行数与 `族内n`；
4. 到 raw 搜同一 `模型 + 来源 + 类别`，核对原始分、量纲、日期、URL；
5. 若怀疑族归属，查 `data/mapping.csv` 的 `(来源, 类别)` 行；
6. 若怀疑重名，查 `data/canon.csv`。

## 20. 已知限制与设计红线

### 20.1 方法本身的限制

| 限制 | 影响 | 缓解 |
|---|---|---|
| **池内相对分** | 增减模型会让全池分数整体移动 | 页面/文档反复标注；跨期只比相对位次 |
| **族划分有主观性** | 把两个基准并族/拆族会改变权重 | 族定义写进 `mapping.csv` 并留备注；一个族只属于一个维度 |
| **小族降权** | n=2/3 位次分辨率粗 | ×0.6/×0.35 降权入分；n=1 仍不计分（单模型无对手） |
| **族级等权** | 大样本族与小样本族同权 | 这是有意选择：避免大池子垄断；单基准用 `†` 标注 |
| **算术平均** | 一个异常族会直接拉动维度分 | 证据抽屉可逐条核查；异常值优先回源核对 |
| **缺数据让权** | 覆盖少的模型综合分只代表“考过的部分” | `n/8` + 「低覆盖」显式标注，不乘惩罚系数 |
| **厂商自报偏差** | 全部来源口径可能被厂商分数影响 | 一键切「仅第三方」；按渠道整体排除 |
| **推理值误差大** | MAE ≈21.5 位次分（2026-10-18 快照） | 默认不计分；只补空格；虚线标识 + 方法/MAE 明示 |
| **Elo 池依赖** | 换一批对比模型 Elo 会变 | 池内 min-max 后仍只用于族内排名；保留 URL 可复核 |
| **TB 版本差** | TB4.0 地板值可能顶掉健康的 TB2.1 | 已知取舍（2026-10-18 试算影响 ≤4 分；池子变动后需重算）；规则单点维护 |
| **`0-1越低越好` 未实现** | 幻觉率类指标不能入账 | 有意不映射；误映射会硬失败 |
| **推理快照过期** | 新模型没有推理值、旧值基于旧池 | 明确标日期；重跑是独立数据轮，不随日常构建 |

### 20.2 来源本身的限制

| 来源 | 限制 |
|---|---|
| Artificial Analysis | 字段缺失/改版；部分模型无 IFBench、τ²、GPQA、MMMU-Pro |
| LiveBench 1.x / 2.0 | release 固定；2.0 未收录所有模型；两版不并族 |
| SuperCLUE | 版本多、只收精确同款；Writing 当前 n=5；总榜与分项重复，只用分项 |
| LMArena | Cloudflare 限制；总榜与类目模型集不同；只取 WebDev / Vision |
| Design Arena | 混合图片理解与前端设计，不是纯识图 |
| AIWB | 英文写作；与中文写作不可直接比 |
| AI产品狙击手 | 单题、单人主观、渠道/思考档不一；只作独立族 |
| 厂商官方 | 选择性偏差；设置/版本不明确的不收 |
| 酥悠沫 | 二次聚合；能回原厂优先原厂；转录厂商表单独标渠道 |

### 20.3 设计红线（勿推翻）

1. **速度 / 成本不进雷达轴。** 需要性价比就另做图外散点，且要重抓价格数据。
2. **不做未加权均值表盘。** 场景权重是核心表达。
3. **负值 / 差值不上雷达。**
4. **每张图只用一种口径，并标注数据日期。**
5. **缺数据 ≠ 0。** 雷达断开、条形斜纹、矩阵斜纹、轴端空心圈；不得把缺失画成 0。
6. **榜单改版只改两张表**：`mapping.csv`（来源×类别→维度+族）与 `canon.csv`（榜单名→统一名）；不要在代码或文档里另抄映射。
7. **厂商渠道名单只有一处**：`build_scores.VENDOR_SRC`；`build_html.py` 复用。
8. **同一基准只算一票**：族去重 + TB 单版本 + 小族降权（n≥2 入分）。
9. **维度分 = 计分族位次分算术平均**；不按 n 加权、不按来源摊权。
10. **推理值不静默混入实测**；默认不计分，页面可切换。
11. **不绕过访问控制**；Cloudflare/403 的来源宁可不接。
12. **不制造幻影模型**：删模型要同时清 raw / canon / mapping / models，并重跑校验。

| **面值** | 原始分经量纲折算后的 0–100 分，只用于族内排名 |
| **基准族（族）** | 同一基准/同一套题的不同报法；同族只留一票 |
| **族内 n** | 该族当前池内的模型数（去重后） |
| **位次分** | `(族内升序名次−0.5)/n×100`；赢过池内多少比例的对手 |
| **计分族** | n≥2、实际参与维度均值的族（n=2/3 降权） |
| **样本不足** | n<4；证据保留但不计分 |
| **单基准 `sf`** | 某维只由 1 个族支撑；页面加 `†` |
| **口径** | 全部来源 / 仅第三方 / 含推理补全 |
| **空格** | 某（模型,维度）没有任何计分证据 |
| **待定** | 模型没有任何计分证据（如 Space-Bunny） |
| **推理补全** | M1/M2 生成的估计值，默认不计分 |
| **覆盖度** | 有分维度数 `n/8`；权重覆盖 = 有分维度权重和 / 总权重 |
| **低覆盖** | 权重覆盖 <60%；标「·低覆盖」，不惩罚 |
| **≈平** | 两候选差 <2 分，不判胜负 |
