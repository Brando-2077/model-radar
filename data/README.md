# 数据目录说明

`data/` 是项目的证据账本与口径表。主链路只依赖这里的 CSV：

```text
raw_*.csv ─┐
mapping.csv ├─> build_scores.py ─> scores.csv ─> build_html.py ─> model-radar.html
canon.csv ─┘
```

## 1. 文件一览

| 文件 | 类型 | 说明 |
|---|---|---|
| `raw_aa_lmarena.csv` | 原始证据 | Artificial Analysis 单模型页 + LMArena 人评 Elo |
| `raw_livebench.csv` | 原始证据 | LiveBench 1.x 官方分类别表 |
| `raw_livebench2.csv` | 原始证据 | LiveBench 2.0 官方 release 七套件 |
| `raw_superclue.csv` | 原始证据 | SuperCLUE 通用/长上下文/Terminal/Writing 等 |
| `raw_aiwb.csv` | 原始证据 | AIWB 英文写作盲评 |
| `raw_design_arena.csv` | 原始证据 | Design Arena `models-website` 人评 Elo |
| `raw_tgg_q1.csv` | 原始证据 | AI产品狙击手 Q1 中文指令遵循 |
| `raw_vendor.csv` | 原始证据 | 厂商官方模型卡/发布页（厂商自报渠道） |
| `raw_suyoumo.csv` | 原始证据 | 酥悠沫聚合榜补缺（第三方 + 官方转录） |
| `raw_inferred.csv` | 推理补全 | 缺失格的估计值，默认不计分 |
| `mapping.csv` | 口径表 |（来源, 类别）→ 维度 + 基准族 |
| `canon.csv` | 口径表 | 榜单模型名 → 项目统一名 |
| `models.csv` | 名册 | 模型、公司、开源、数据日期、备注 |
| `dimensions.csv` | 定义 | 8 维定义、白话解释、典型任务、适用建议 |
| `weights.csv` | 权重 | 5 套场景 × 8 维相对权重 |
| `scores.csv` | **生成物** | `build_scores.py` 的输出，勿手改 |

## 2. raw 表的列

除 `raw_inferred.csv` 外，所有 `raw_*.csv` 的列为：

```csv
模型,公司,来源,类别,原始分,量纲,数据日期,URL
```

| 列 | 说明 |
|---|---|
| `模型` | 榜单上的原名；由 `canon.csv` 转成统一名 |
| `公司` | 来源页标注的厂商；可空，构建时会从其他行反查 |
| `来源` | 稳定来源名，如 `Artificial-Analysis`、`LiveBench-2.0`、`SuperCLUE` |
| `类别` | 来源内部的基准/类目名，必须与 `mapping.csv` 的 `类别` 完全一致 |
| `原始分` | 照抄来源，不预先归一化 |
| `量纲` | `0-100` / `百分制` / `0-1` / `0-1越低越好` / `10分制` / `5分制` / `Elo` / `指数` |
| `数据日期` | 来源页面标注的日期，不是抓取日 |
| `URL` | 能回到该条证据的页面 |

### 示例

```csv
模型,公司,来源,类别,原始分,量纲,数据日期,URL
Claude-Fable-5.1,Anthropic,Artificial-Analysis,GPQA,0.912,0-1,2026-10-20,https://artificialanalysis.ai/models/claude-fable-5-1
```

同一模型页的多条证据，每行都写同一个 URL；不要合并成一行。

## 3. `raw_inferred.csv`

列不同：

```csv
模型,维度,推理分,推理方法,依据,留一MAE,数据日期,URL
```

- 只填“该（模型, 维度）没有任何计分证据”的格子；
- 不覆盖实测；
- 默认不计入维度分；
- `依据` 必须写清用了哪些同族/近邻模型、哪些基准；
- `留一MAE` 是方法在已知格上的留一验证误差，不是拍脑袋的置信度；
- 页面在“含推理补全”口径下用虚线/斜体标注。

## 4. `mapping.csv`

```csv
来源,类别,维度,族,备注
```

- `维度` 必须是 `dimensions.csv` 中的 8 个之一；
- `维度` 留空 = **有意不映射**（总分、综合指数、无法归族的字段）；不要用空值表示“忘了填”；
- `族` 是基准族名：同一基准的不同报法用同一个族名；不同基准不要为了凑人数并族；
- 每个 raw 的（来源, 类别）都必须在这里出现，否则 `build_scores.py` 会提示未映射；
- 新增/修改族会影响全池位次分，属于口径变更，PR 里要说明。

## 5. `canon.csv`

```csv
榜单名,统一名,备注
```

- `榜单名` 必须与 raw 里的 `模型` 完全一致（空格、括号、大小写）；
- 一个榜单名只能映射到一个统一名；
- 删除模型时，同时删掉对应别名，避免幻影模型。

## 6. `models.csv`

```csv
模型,公司,开源,数据日期,备注
```

- `模型` 用统一名；
- `公司` 可空，构建时会从 raw 反查；
- `开源`：`是` / `否` / `未确认`；判定标准是权重是否可公开下载；
- `数据日期`：发布/快照日期，不是今天；可留空（raw 行的数据日期必填）；
- `备注` 会显示在证据抽屉与悬停提示；写上下文、参数、已知缺口、TB 版本差异。

待定模型也在这里占位，例如无公开 benchmark 的 stealth 模型；不要为它编造 raw 行。

## 7. `dimensions.csv`

```csv
维度,一句话定义,典型公开数据源（榜单分）,备注,口径说明,通俗解释,典型任务,适用建议,白话
```

8 行，对应 8 个能力维度。页面抽屉、条形图标签、逐维对照都读取这张表。改定义会影响读者理解，但不直接改分数。

## 8. `weights.csv`

```csv
场景,维度,权重
```

- 5 套场景 × 8 维 = 40 行；
- `权重` 是**相对值**，不要求每套场景直接加总 100；
- `build_html.py` 会按场景归一化到 100.0，页面显示归一后的百分比；
- 改权重会改变场景综合分与榜位，属于产品口径变更，先开 Issue 讨论。

## 9. `scores.csv`（生成物）

```csv
模型,维度,榜单分,备注,族,族内n
```

- `榜单分`：族内位次分（0–100，1 位小数）；
- `族`：基准族名；推理行的族为空；
- `族内n`：该族去重后的模型数；推理行为空；
- `族内n < 4` 的行保留面值与真实人数，页面过滤并标“样本不足”；
- **不要手改**。改 raw / mapping / canon 后跑 `python build_scores.py`。

当前规模（2026-10-21）：

- 729 条证据（实测 716 + 推理 13）；
- 669 条计分证据；
- 44 个计分族；
- 234 个有分格子；
- 33 个模型（32 个有分 + 1 个待定）。

这些数字会随数据更新变化，以 `scores.csv` 和 `scripts/validate.py` 的输出为准。

## 10. 数据纪律

1. 每行都要有来源 URL 与数据日期；
2. 只收精确同款版本；
3. 同一（模型 × 族）只留一票：第三方优先、日期新者优先；
4. 族内 <4 不计分，不硬凑；
5. 缺数据保持空白，不写 0；
6. 厂商自报只用于该厂商自己的模型；
7. 推理值只进 `raw_inferred.csv`，默认不计分；
8. 删除模型时清理所有表，避免幻影模型。

完整口径见 [docs/methodology.md](../docs/methodology.md)，加模型流程见 [docs/adding-models.md](../docs/adding-models.md)。
